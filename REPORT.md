# Звіт з тестування продуктивності додатку за допомогою Apache JMeter

## 1. Середовище тестування

- Операційна система: Windows
- Apache JMeter: 5.x (стабільна версія)
- Java: JDK 8+
- Додаток, що тестується: QA Pro REST App
- Тип розгортання: локальний Docker-контейнер
- Базовий URL: http://localhost:8080

---

## 2. Мета роботи

Метою даної роботи є набуття практичних навичок використання Apache JMeter для тестування продуктивності REST API додатку, збору та аналізу метрик, а також оцінки поведінки системи під різними типами навантаження.

---

## 3. Тестовані ендпоїнти

У межах тестування були використані наступні REST API ендпоїнти:

- `GET /characters`
- `GET /character/{id}`
- `POST /character`

---

## 4. Кореляція та робота з динамічними даними

Для забезпечення коректної роботи з динамічними параметрами була реалізована кореляція:

- У відповіді запиту `GET /characters` за допомогою **JSON Extractor** автоматично витягується значення `id`.
- Отримане значення `id` використовується у наступному запиті `GET /character/{id}`.
- Такий підхід дозволяє уникнути використання статичних даних та забезпечує стабільну роботу тестів.

---

## 5. Параметризація тестових даних

Для створення реалістичного навантаження була використана параметризація:

- Дані для створення персонажів зчитуються з CSV-файлу `characters.csv`.
- Параметризація реалізована за допомогою **CSV Data Set Config**.
- Це дозволяє використовувати унікальні тестові дані та запобігає конфліктам при виконанні тестів.

---

## 6. Сценарії навантаження

У тест-плані були реалізовані наступні сценарії:

### 6.1 Concurrency Thread Group (короткий тест)
- Кількість користувачів: 30
- Мета: перевірка поведінки системи при одночасному навантаженні

### 6.2 Stepping Thread Group
- Кількість користувачів: до 30
- Навантаження збільшується поступово
- Мета: аналіз стабільності системи при поетапному зростанні навантаження

### 6.3 Concurrency Thread Group (довгий запуск)
- Кількість користувачів: 15
- Тривалість тесту: 30 хвилин
- Результати тестування:
  - Aggregate CSV: `results/aggregate_longrun_30min.csv`
  - JTL файл: `results/results_htmlrun.jtl`
  - HTML звіт: `html-report/index.html`

---

## 7. Використання Listener-ів та моніторинг метрик

Для збору, аналізу та візуалізації метрик під час виконання тестів використовувалися стандартні Listener-и Apache JMeter:

- **Aggregate Report** — для аналізу пропускної здатності, середнього часу відповіді та відсотка помилок
- **Response Times Over Time** — для аналізу зміни часу відповіді під навантаженням
- **Active Threads Over Time** — для контролю кількості активних користувачів
- **HTML Report** — для підсумкового аналізу результатів тестування

Скріншоти ключових графіків збережені у папці `screenshots/`.

---

## 8. Моніторинг ресурсів та поведінки системи

Моніторинг поведінки системи під час виконання навантажувальних тестів здійснювався за допомогою стандартних Listener-ів JMeter.

Аналізувалися наступні показники:
- кількість активних потоків;
- час відповіді сервера;
- пропускна здатність та відсоток помилок.

Дані метрики дозволяють оцінити стабільність роботи додатку та непряме навантаження на системні ресурси (CPU, памʼять) під час виконання тестів.

Використання PerfMon Listener або інших інструментів для прямого моніторингу серверних ресурсів не виконувалося у звʼязку з локальним розгортанням додатку в Docker-контейнері без встановлених агентів моніторингу.

---

## 9. Аналіз результатів тестування

- Під час виконання GUI-тестів відсоток помилок склав **0.00%**.
- Під час довгого навантажувального тесту зафіксовані поодинокі помилки типу:
  - `org.apache.http.NoHttpResponseException (localhost:8080 failed to respond)`
- Загальна кількість помилок: **8 із 4929 запитів (~0.16%)**.
- Помилки мали несистемний характер та повʼязані з локальним середовищем виконання.

---

## 10. Висновки та рекомендації

- Навантажувальні сценарії були успішно виконані.
- Система демонструє стабільну роботу під різними типами навантаження.
- Реалізовані параметризація, кореляція та різні сценарії навантаження відповідають вимогам навчального завдання.
- Для більш глибокого аналізу у майбутньому доцільно використовувати інструменти прямого моніторингу ресурсів (наприклад, PerfMon Listener) за умови доступу до серверного середовища.
